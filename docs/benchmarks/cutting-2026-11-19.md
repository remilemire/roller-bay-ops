## Exact-fill searches

The synthetic generator constructs and validates a witness before giving the planner only the blinds and stock. Each requested layout exactly fills its available fabric. Three, four or five side-by-side blinds per cut in the witness produce different search difficulty at similar order sizes.

Of 18 cases, 15 found a validated plan within the benchmark's two-second observation window. The three still searching had 40, 50 and 60 blinds and witnesses with five blinds per cut. With a longer window the 40-blind case found a validated plan in **10.08 s**, after 2,138,300 backtracks. The 50-blind case was still searching after **60 s** and 6,893,531 backtracks. It was explicitly cancelled by the benchmark. A running application job has no such search deadline.

## Reproduction

After installing the repository dependencies and the solver virtual environment, build the shared contracts and API test output. The inventory benchmark accepts the saved JSON snapshot as a positional argument. The exact-fill benchmark generates all its own data.

```sh
npm run build --workspace=@roller-bay/shared
npm run test:build --workspace=@roller-bay/api
python3 scripts/benchmark-cutting-pressure.py /path/to/inventory.json > inventory-results.jsonl
node scripts/benchmark-cutting-tight.mjs
node scripts/benchmark-cutting-tight.mjs 120000 5 8
node scripts/benchmark-cutting-tight.mjs 60000 5 10
```
